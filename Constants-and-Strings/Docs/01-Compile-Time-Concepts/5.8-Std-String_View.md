### TÓM TẮT TOÀN DIỆN: C++ `std::string_view` (Part 1 & 2)

### 1. Tính linh hoạt trong Khởi tạo và Làm tham số (Part 1)
`std::string_view` được sinh ra để làm tham số "quốc dân". Nó có thể chấp nhận hầu hết mọi loại chuỗi truyền vào mà không gặp vấn đề gì.

**Code minh họa:**
```cpp
#include <iostream>
#include <string>
#include <string_view>

void printSV(std::string_view str) {
    std::cout << str << '\n';
}

int main() {
    // Khởi tạo và truyền C-style string literal
    std::string_view s1 { "Hello, world!" }; 
    std::cout << s1 << '\n';

    // Khởi tạo và truyền std::string
    std::string s2 { "Hello, world!" };
    printSV(s2);

    // Khởi tạo và truyền std::string_view
    std::string_view s3 { s2 };
    printSV(s3);

    return 0;
}
```

### 2. Bản chất của Phép gán - Assignment (Part 1)
Phép gán chỉ thay đổi vị trí mà cái "kính lúp" `std::string_view` đang chĩa vào, hoàn toàn **không làm thay đổi** dữ liệu của chuỗi gốc.

**Code minh họa:**
```cpp
#include <iostream>
#include <string>
#include <string_view>

int main() {
    std::string name { "Alex" };
    std::string_view sv { name }; // sv đang nhìn vào biến name ("Alex")
    
    std::cout << sv << '\n'; // In ra Alex

    sv = "John"; // sv chuyển sang nhìn chuỗi "John" (không làm thay đổi name)

    std::cout << sv << '\n';   // In ra: John
    std::cout << name << '\n'; // In ra: Alex (Chuỗi gốc KHÔNG bị ảnh hưởng)
    
    return 0;
}
```

### 3. Chuyển đổi ngược - Implicit Conversion (Part 1)
Ngược lại với tính linh hoạt ở mục 1, `std::string_view` sẽ **KHÔNG** tự động (ngầm định) chuyển đổi ngược lại thành `std::string` để tránh lãng phí hiệu năng do copy ngoài ý muốn. Bạn phải ép kiểu tường minh.

**Code minh họa:**
```cpp
#include <iostream>
#include <string>
#include <string_view>

void printString(std::string str) {
    std::cout << str << '\n';
}

int main() {
    std::string_view sv { "Hello, world!" };

    // printString(sv); // LỖI BIÊN DỊCH: Không ngầm định convert view thành string
    
    // Hợp lệ: Ép kiểu rõ ràng (tạo ra một bản copy std::string từ view)
    printString(static_cast<std::string>(sv)); 
    
    return 0;
}
```

### 4. Hằng số thời gian biên dịch - `constexpr` (Part 1)
Khác với `std::string` thông thường, `std::string_view` hỗ trợ toàn diện cho `constexpr` (tính toán hằng số thời gian biên dịch).

**Code minh họa:**
```cpp
#include <iostream>
#include <string_view>

int main() {
    // Hợp lệ: string_view hoạt động hoàn hảo với constexpr
    constexpr std::string_view sv { "Hello, world!" }; 
    std::cout << sv << '\n';

    return 0;
}
```

### 5. Hậu tố Literal - `sv` (Part 1)
Bạn có thể tạo ra các hằng số `std::string_view` trực tiếp bằng cách thêm hậu tố `sv` vào sau chuỗi (cần mở khóa namespace `std::string_view_literals`).

**Code minh họa:**
```cpp
#include <iostream>
#include <string_view>

int main() {
    // Phải có dòng này mới dùng được hậu tố 'sv'
    using namespace std::string_view_literals; 

    std::cout << "foo\n";    // Không có hậu tố: Là C-style string
    std::cout << "moo\n"sv;  // Hậu tố sv: Là std::string_view literal

    return 0;
}
```

### Bảng Tóm Tắt Bài Học: C++ `std::string_view` (Part 2)

| Khái niệm cốt lõi | Giải thích ngắn gọn (TL;DR) | Đặc điểm / Lưu ý sinh tử |
| :--- | :--- | :--- |
| **1. Bản chất "The Viewer" (Kính quan sát)** | `std::string_view` giống như một cái cửa sổ nhìn vào một chuỗi đã có sẵn. Nó **không copy** và **không sở hữu** dữ liệu. | Rất nhẹ, khởi tạo cực kỳ nhanh. Phù hợp tuyệt đối cho việc chỉ-đọc (read-only). |
| **2. Dangling View (Góc nhìn "treo")** | Lỗi nghiêm trọng nhất! Xảy ra khi chuỗi gốc (ngôi nhà) bị đập đi hoặc sửa chữa, nhưng cái view (cửa sổ) của bạn vẫn đang nhìn vào vị trí đó. | Gây ra **Undefined Behavior** (Chương trình có thể crash hoặc in ra rác). Bạn luôn phải đảm bảo chuỗi gốc sống thọ hơn cái view. |
| **3. Trả về View từ Hàm (Return by value)** | Tuyệt đối **không** trả về một `std::string_view` trỏ tới một biến cục bộ (vì biến cục bộ sẽ bị hủy ngay khi hàm kết thúc, tạo ra Dangling View). | Chỉ an toàn nếu bạn trả về một view trỏ tới các chuỗi hằng (literal có hậu tố `sv`), biến toàn cục (`static`), hoặc view được truyền từ ngoài vào. |
| **4. Thu hẹp góc nhìn (Windowing)** | Bạn có thể dùng `remove_prefix()` (cắt ký tự bên trái) hoặc `remove_suffix()` (cắt ký tự bên phải) để thay đổi phạm vi quan sát của view. | Chỉ làm nhỏ lại góc nhìn của cái view, **tuyệt đối không làm suy xuyển hay thay đổi chuỗi gốc**. |
| **5. Thực hành tốt nhất (Best Practice)** | Từ C++17, nếu bạn viết một hàm chỉ cần **đọc** chuỗi, hãy dùng `std::string_view` làm tham số thay vì `const std::string&`. | Đừng dùng `std::string_view` nếu hàm của bạn cần thay đổi nội dung chuỗi gốc, hãy giữ lại `std::string`. |

**Cách tiếp cận khi đọc bài:**
Khi bạn đọc tài liệu gốc, hãy dồn toàn bộ sự chú ý vào phần **Dangling View**. Đó là cạm bẫy lớn nhất mà bài 2 này muốn cảnh báo. Các phần hàm `remove_prefix` hay `remove_suffix` chỉ là công cụ bổ trợ, bạn có thể đọc lướt qua để biết cách xài là đủ!
