# File 1: Constant Expression vs Runtime Expression (Bài 5.5)

Bản tóm tắt này giúp phân biệt rạch ròi giữa những gì Trình biên dịch (Compiler) làm và những gì Chip (Runtime) phải làm trong quá trình thực thi chương trình.

## 1. Mã nguồn thực hành (Core Principles)

```cpp
#include <iostream>

// 💡 [CONCEPT] Hàm này thiết kế cho ngữ cảnh yêu cầu giá trị hằng số ngay lúc biên dịch.
constexpr int function_for_constant_expression1() 
{ // 🔩 [COMPILER] Cấp quyền cho Trình biên dịch tự chạy và tính toán hàm này ngay trên máy tính của bạn.
    return 10; // ⚙️ [PROCESSING] Trình biên dịch giải mã lệnh này, tự động thay thế mọi nơi gọi hàm thành số cứng 10.
} // 🚀 [PERFORMANCE] Kết thúc biên dịch, hàm này "bốc hơi" khỏi chương trình thực tế. Chip không tốn chu kỳ máy (clock cycles).

// 👤 [HARDWARE] Hàm này thiết kế cho ngữ cảnh thời gian thực (Runtime), Chip đang hoạt động.
int not_function_for_constant_expression1() 
{ // 📦 [ASSEMBLY] Thực chất đóng gói lệnh thành mã hợp ngữ để nạp xuống cho CPU.
    return 10; // 📥 [INPUT/I-O] CPU thực sự phải nạp số 10 vào thanh ghi và thực hiện lệnh trả về.
} // 🚀 [PERFORMANCE] Tình trạng sau kết thúc: CPU tốn thời gian thực thi lệnh nhảy và lưu kết quả vào RAM.

int main() {
    std::cout << "========== DEMO: CONSTANT EXPRESSION ==========\n";

    // ✅ [PASS VÌ: Trình biên dịch có thể tự cộng 5 + 3 ngay trên máy tính trước khi build. Giá trị 8 được khóa thẳng vào mã máy.]
    constexpr int constant_expression1 = 5 + 3;

    // ✅ [PASS VÌ: Hàm là constexpr, Trình biên dịch tự gọi hàm và nhân 2 để thay thế bằng số cứng 20 ngay lúc build.]
    constexpr int constant_expression3 = function_for_constant_expression1() * 2;

    // ✅ [PASS VÌ: Trong C++, biến const int được gán số cứng (128) được đặc cách coi là Constant Expression. Trình biên dịch biết chắc cần cấp đúng 128 phần tử RAM.]
    const int constant_expression2 = 128;
    int valid_array[constant_expression2];
    
    // ---------------------------------------------------------
    // KHU VỰC LỖI THỜI GIAN BIÊN DỊCH (COMPILE-TIME ERRORS)
    // ---------------------------------------------------------
    
    int not_constant_expression1 = 50;
    
    // ⚠️ [WARNING: Không phải lỗi biên dịch. Lúc chạy (Runtime), lệnh này gọi hàm bình thường, lưu vào bộ nhớ, và sau đó biến bị khóa lại (chỉ đọc).]
    const int not_constant_expression4 = not_function_for_constant_expression1(); 

    // ❌ [FAIL VÌ: Trình biên dịch cần chốt số lượng bytes để cấp phát mảng tĩnh trước khi nạp xuống chip, nhưng not_constant_expression1 lại đang "giấu" giá trị trên RAM đợi lúc chạy.]
    // int invalid_array_1[not_constant_expression1]; 
    // Uncomment dòng trên: variable-sized object may not be initialized

    return 0;
}
```

## 2. Phụ lục 1: Giải thích Code chi tiết

* **`constant_expression2` (Đặc cách)**: Trong C++, một biến `const int` được khởi tạo bằng một hằng số sẽ được coi là một *Constant Expression*. Điều này giúp code cũ vẫn tương thích tốt, nhưng với C++ hiện đại, bạn nên ưu tiên `constexpr`.
* **Sự "lây nhiễm" Runtime**: Chỉ cần một thành phần trong phép tính là biến thời gian chạy (ví dụ `not_constant_expression1`), toàn bộ kết quả của phép tính đó sẽ bị coi là Runtime Expression.
* **Ứng dụng Mảng tĩnh**: Trình biên dịch cần biết chính xác con số để đặt chỗ trên RAM trước khi chương trình bắt đầu. Đó là lý do tại sao chỉ có *Constant Expression* mới được nằm trong dấu `[]` của mảng C-style.

# Tóm tắt cốt lõi: Constant Expression & constexpr

1. **Constant Expression (Khái niệm)**: Là những phép tính mà Trình biên dịch có thể tự giải mã xong xuôi ngay trên máy tính của bạn trước khi nạp code xuống vi điều khiển.
2. **Lợi ích**: Tiết kiệm 100% chu kỳ máy (clock cycles) vì chip không phải thực hiện lại các phép tính cố định này trong lúc đang chạy thực tế (Runtime).
3. **`constexpr` (Công cụ)**: Là từ khóa dùng để "ra lệnh cưỡng chế" Trình biên dịch phải xác nhận và khóa một giá trị ngay tại thời điểm biên dịch.
4. **Cơ chế an toàn**: Nếu bạn gán một giá trị dính líu đến thời gian chạy (như hàm đọc cảm biến) cho biến `constexpr`, C++ sẽ báo lỗi biên dịch ngay lập tức.
5. **Thực chiến**: Luôn dùng `constexpr` để định nghĩa kích thước mảng buffer, số thứ tự chân GPIO, địa chỉ thanh ghi và các cấu hình hệ thống bất biến.
