# File 2: Từ khóa constexpr - Lệnh Cưỡng Chế (Bài 5.6)

Bài này tập trung vào công cụ `constexpr` để đảm bảo hiệu năng tối đa cho hệ thống nhúng bằng cách ép buộc tính toán tại thời điểm biên dịch.

## 1. Mã nguồn thực hành (Core Principles)

```cpp
#include <iostream>

// 👤 [HARDWARE] Hàm này thiết kế cho các biến/tham số nhận giá trị từ ngoại vi ở thời gian chạy (Runtime).
int read_sensor_runtime() 
{ // 📦 [ASSEMBLY] Thực chất đóng gói lệnh thành mã hợp ngữ để yêu cầu CPU giao tiếp với cảm biến.
    return 30; // 📥 [INPUT/I-O] CPU tốn chu kỳ máy đọc dữ liệu ngoại vi và nạp số 30 vào thanh ghi.
} // 🚀 [PERFORMANCE] Tình trạng sau kết thúc: CPU tốn thời gian thực thi lệnh nhảy và lưu kết quả vào RAM.

// 💡 [CONCEPT] Hàm này thiết kế cho cấu hình hệ thống (Baud rate) yêu cầu giá trị hằng số lúc biên dịch.
constexpr int calculate_baud_rate(int multiplier) 
{ // 🔩 [COMPILER] Cấp quyền cho Trình biên dịch tự chạy và tính toán hàm này lúc build.
    return 1200 * multiplier; // ⚙️ [PROCESSING] Trình biên dịch thực hiện phép nhân và thay thế kết quả thành số cứng.
} // 🚀 [PERFORMANCE] Kết thúc biên dịch, hàm này "bốc hơi". Code máy chỉ còn con số kết quả tĩnh.

int main() {
    std::cout << "========== DEMO: CONSTEXPR ==========\n";

    // ✅ [PASS VÌ: const bình thường chấp nhận lấy giá trị lúc vi điều khiển đang chạy (runtime) và khóa lại vào RAM]
    const int const_runtime = read_sensor_runtime();
    
    // ✅ [PASS VÌ: Hàm calculate_baud_rate là constexpr và tham số truyền vào là số cứng (8). Trình biên dịch tính ra luôn 9600]
    constexpr int constexpr_calculated = calculate_baud_rate(8); 
    
    // ✅ [PASS VÌ: Kích thước mảng được chia từ một biểu thức constexpr (9600 / 1200 = 8), an toàn tuyệt đối về bộ nhớ tĩnh]
    int buffer_3[constexpr_calculated / 1200];       
    
    // ---------------------------------------------------------
    // KHU VỰC LỖI THỜI GIAN BIÊN DỊCH (COMPILE-TIME ERRORS)
    // ---------------------------------------------------------

    // ❌ [FAIL VÌ: Từ khóa constexpr mang tính "cưỡng chế", trình biên dịch từ chối lấy dữ liệu cảm biến vì code còn chưa được nạp xuống chip]
    // constexpr int constexpr_invalid = read_sensor_runtime(); 
    // Uncomment dòng trên: constexpr variable 'constexpr_invalid' must be initialized by a constant expression

    // ❌ [FAIL VÌ: Không thể dùng giá trị nhiệt độ của cảm biến trên RAM (chưa biết là bao nhiêu lúc compile) để chốt kích thước vùng nhớ tĩnh]
    // int buffer_2[const_runtime]; 
    // Uncomment dòng trên: variable-sized object may not be initialized

    return 0;
}
```

## 2. Phụ lục 1: Giải thích Code chi tiết

* **`const` vs `constexpr`**: `const` có nghĩa là "chỉ đọc" (Read-only), còn `constexpr` có nghĩa là "Chỉ đọc VÀ Bắt buộc tính sẵn lúc biên dịch".
* **Cơ chế an toàn**: Nếu bạn gán một giá trị dính líu đến thời gian chạy (như hàm đọc cảm biến) cho biến `constexpr`, C++ sẽ báo lỗi biên dịch ngay lập tức.
* **Thực chiến**: Luôn dùng `constexpr` để định nghĩa kích thước mảng buffer, số thứ tự chân GPIO, địa chỉ thanh ghi và các cấu hình hệ thống bất biến.

# Tóm tắt cốt lõi: Constant Expression & constexpr

1. **Constant Expression (Khái niệm)**: Là những phép tính mà Trình biên dịch có thể tự giải mã xong xuôi ngay trên máy tính của bạn trước khi nạp code xuống vi điều khiển.
2. **Lợi ích**: Tiết kiệm 100% chu kỳ máy (clock cycles) vì chip không phải thực hiện lại các phép tính cố định này trong lúc đang chạy thực tế (Runtime).
3. **`constexpr` (Công cụ)**: Là từ khóa dùng để "ra lệnh cưỡng chế" Trình biên dịch phải xác nhận và khóa một giá trị ngay tại thời điểm biên dịch.
4. **Cơ chế an toàn**: Trình biên dịch sẽ ngăn chặn các lỗi logic liên quan đến việc gán giá trị thời gian chạy cho hằng số biên dịch.
5. **Thực chiến**: Đặc biệt quan trọng trong lập trình nhúng để tối ưu hóa bộ nhớ và hiệu suất.
