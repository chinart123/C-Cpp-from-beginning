## 3. CÁC PHIÊN BẢN LỖI VÀ QUÁ TRÌNH TIẾN HÓA TƯ DUY

### Sai lầm 1: Ép hàm `constexpr` làm việc ở runtime (I/O)
Cố gắng đưa các lệnh nhập/xuất vào hàm `constexpr`, dẫn đến lỗi biên dịch vì máy tính không thể "nhập dữ liệu từ tương lai" khi đang build app.
```cpp
constexpr int isEven(const int isInteger)
{
    // LỖI: cout và cin là tác vụ Runtime. 
    std::cout << "Please enter a number: "; 
    constexpr int x{}; 
    std::cin >> x;   // LỖI: Không thể gán giá trị từ cin vào hằng số constexpr.
    x = isInteger;   // LỖI: Luồng dữ liệu tự triệt tiêu.
}
```
* **Bài học:** Hàm `constexpr` phải "sạch" (Pure Function) – chỉ nhận tham số và tính toán, không giao tiếp màn hình/bàn phím.

### Sai lầm 2: Lạm dụng `assert` và Cạm bẫy số lẻ âm
Sau khi tách được I/O ra ngoài, logic kiểm tra bằng `assert` và `> 0` lại gây họa.
```cpp
constexpr int isEven(const int isInteger)
{
    // SAI LẦM: assert sẽ ép chương trình CRASH nếu truyền số lẻ. 
    assert( (isInteger % 2) == 0 && "The number is not even"); 

    if ((isInteger % 2) == 0) {
        std::cout << "The number is even"; 
    }
    // CẠM BẪY SỐ ÂM: Nếu truyền -5, (-5 % 2) sẽ ra -1. (-1 > 0) là SAI.
    // Kết quả: Chương trình bỏ sót hoàn toàn số lẻ âm.
    if ((isInteger % 2) > 0) { 
        std::cout << "The number is odd";
    }
    return 0;
}
```
* **Bài học:** Không dùng `assert` để rẽ nhánh chương trình. Phần dư của số âm mang dấu âm, tuyệt đối không check số lẻ bằng cách so sánh `> 0` hay `== 1`.

### Sai lầm 3: Ôm đồm nhiệm vụ và sai kiểu trả về
Đề bài yêu cầu trả về `true/false`, nhưng hàm vẫn đang trả về `int` và khai báo biến dư thừa.
```cpp
constexpr int isEven(const int isInteger) // Sai kiểu trả về (đang là int)
{
    bool Even{true};  
    bool Odd{true};   // Lỗi: Cả chẵn/lẻ đều gán true làm mất ý nghĩa phân loại

    if ((isInteger % 2) == 0) {
        std::cout << "The number is even";  
        return Even; // Sẽ bị ép kiểu ngược thành int (1)
    }
    // ...
}
```
* **Bài học - Separation of Concerns:** Hàm logic chỉ làm toán và trả thẳng `true/false`. Việc `cout` phải đẩy ra ngoài hàm `main()`.

## 4. GIẢI PHÁP HOÀN THIỆN (PHIÊN BẢN FIX)

Bám sát định nghĩa duy nhất: **Số chẵn là số có số dư bằng 0 khi chia cho 2 (đúng với cả số 0, âm và dương).**

**Cách 1: Cấu trúc rẽ nhánh (Dễ đọc cho người mới)**
```cpp
constexpr bool isEven(const int isInteger)
{
    if ((isInteger % 2) == 0) {
        return true;
    } else {
        return false;
    }
}
```

**Cách 2: Bí kíp "1 dòng" (Clean code, chuyên nghiệp)**
Bản thân biểu thức so sánh đã tự sinh ra kết quả `true`/`false`.
```cpp
constexpr bool isEven(const int isInteger)
{
    return (isInteger % 2) == 0; 
}
```

**Cấu trúc hàm main() kết nối với giao diện:**
```cpp
#include <iostream>

int main()
{
    int userInput{}; 
    std::cout << "Please enter an integer: ";
    std::cin >> userInput;

    // Lấy kết quả từ hàm logic để quyết định việc in ra màn hình
    if (isEven(userInput)) {
        std::cout << "The number is even\n";
    } else {
        std::cout << "The number is odd\n";
    }

    return 0;
}
```

## 5. PHÂN TÍCH MỞ RỘNG (Q&A TỪ LEARNCPP)

### 5.1. Tại sao compiler gợi ý thêm `static`? (VD: `static constexpr bool isEven`)
* **Ý nghĩa:** Khi hàm nằm ngoài `main` và không thuộc class nào, chữ `static` tạo ra **Internal Linkage**. Nghĩa là hàm này chỉ được phép sử dụng nội bộ bên trong file `.cpp` hiện tại.
* **Lợi ích:** Trình biên dịch có thể tối ưu hóa mã máy tốt hơn vì nó biết chắc chắn không có file nào khác gọi đến hàm này.

### 5.2. Toán tử ba ngôi (Ternary Operator) và cách đặt tên biến
Dựa trên cuộc thảo luận giữa `dinkband` và `angel`:
```cpp
// Cách 1 (Nghiệp dư): Tạo biến thừa và đặt tên sai chuẩn
bool evenOrOdd{ isEven(x) }; 
std::cout << (evenOrOdd ? "even" : "odd");

// Cách 2 (Chuyên nghiệp): Gọi trực tiếp
std::cout << (isEven(x) ? "even" : "odd");
```
* **Về Naming:** Đặt tên biến `bool` là `evenOrOdd` rất tệ. Nếu nó mang giá trị `true`, người đọc không biết "true" là đúng cho even hay odd. Nếu bắt buộc phải lưu biến, hãy đặt tên là `isEven` (Khi `isEven = true` thì đọc lên hiểu ngay là số chẵn).
* **Về Tối ưu:** Gọi trực tiếp hàm trong toán tử ba ngôi giúp tiết kiệm bộ nhớ, tránh sinh ra biến trung gian vô ích.

### 5.3. Câu chuyện về `assert` trong ví dụ của tác giả
* **Lý thuyết:** Tác giả dùng `assert(isEven(4))` trong bài giảng như một dạng **Unit Test** nhanh để chứng minh code đúng mà không cần viết lệnh `cout`.
* **Thực hành:** Trong bài tập giao tiếp với user, không được dùng `assert` để rẽ nhánh vì nó sẽ làm phần mềm "tự sát" (crash) khi user nhập sai ý. (Sau này chương 9.6 sẽ học `static_assert` để chuyên test các hàm `constexpr` ở compile-time).
